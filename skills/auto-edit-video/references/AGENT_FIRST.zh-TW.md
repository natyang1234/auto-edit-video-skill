# Agent-first A-roll 自動剪輯規格（第一階段）

## 1. 目標

第一階段只處理一件事：讓已安裝本 Skill 的本機 AI Agent 讀取使用者提供的單支 A-roll／口播影片，自行完成剪輯並輸出新的 MP4。

這一階段不需要操作介面、預覽網站、LINE 傳送、社群平台發佈或任何私人傳送路徑。

## 2. 使用者契約

使用者唯一必須提供的資料是本機影片檔。剪輯方向可用自然語言補充，但不是必填的設定表單。

範例：

```text
請用 auto-edit-video 自動剪輯 ./input.mp4
```

```text
請把 ./input.mp4 剪成 YouTube Shorts 長版精華
```

```text
請把 ./input.mp4 做成 TikTok，短中長由你看完內容後自動選
```

```text
請把 ./input.mp4 剪成約 75 秒
```

Agent 必須自行處理工作目錄、轉錄、剪輯決策、輸出與 QA，不應先要求使用者另外準備 Whisper JSON、SRT、manifest 或頁面設定。

## 3. 輸入與輸出

| 項目 | 規格 |
|---|---|
| 必填輸入 | 一個 Agent 有權讀取的本機影片檔 |
| 支援格式 | 任何本機 FFmpeg/ffprobe 能正常解碼的影片格式 |
| 選填指示 | 平台、短／中／長／自動、指定秒數、語言、直式／橫式、是否保留完整內容等自然語言要求 |
| 主要輸出 | 一個新的可播放 MP4；原始影片不可被覆寫 |
| 內部產物 | Agent 可建立轉錄、剪輯決策、cut map 與 QA 檔，但不得要求使用者手動提供 |

30 秒只是短版常用目標，不是固定輸出。時長決策依序採用：使用者指定秒數、平台加短／中／長、使用者要求 Agent 自動選擇、最後才是未指定精華需求時的保守全長清理。

## 4. Agent 執行流程

1. 解析並驗證影片路徑；確認檔案可讀、不是目錄，而且 ffprobe 能找到有效視訊串流。
2. 執行 `auto_edit.py preflight`；`ready: false` 或 `missing_required` 非空時停止並回報真正缺少的依賴。
3. 用 `duration-presets` 讀取平台時長矩陣，解析使用者指定的平台與級距；沒有精華需求時以 `full` 建立專案，需要語意判斷時以 `auto` 建立。
4. 自動建立獨立工作專案；複製或連結原始素材，但不得修改原檔。
5. 優先使用本機 Whisper 相容引擎產生含單字時間碼的轉錄。Agent 自行建立 JSON/SRT；預設不得上傳原始音訊或逐字稿。
6. 若級距為 `auto`，讀完逐字稿後選出能保留完整主張的最短級距，再用 `set-target` 寫回 `project.json`。
7. 匯入轉錄並分開分析停頓、贅字、口吃、重複與說錯重講。
8. 低風險候選可依保守規則自動決定；高風險候選一律保留，除非使用者的自然語言指示已明確涵蓋該刪除。
9. 將使用者本回合的「自動剪輯」要求記錄為低風險剪輯授權，再用 `render_cut.py` 產生新的 MP4。
10. 剪完後重新檢查成品時長、音訊／視訊串流與可播放性；需要字幕或語意核對時，必須重新轉錄剪切後的影片。
11. 執行 `qa_video.py`。只有 QA 未出現阻斷錯誤時，才向使用者回報剪輯完成與成品位置。

## 5. 自動決策規則

Agent 可自動處理的低風險項目：

- 明確、過長而不具修辭作用的停頓；
- 單獨出現且沒有語意的贅字；
- 緊鄰、短促，且後一次完整包含前一次內容的口吃；
- 使用者已明示要取用的完整連續片段之外的內容。

Agent 不可自行刪除的高風險項目：

- 包含人名、數字、單位、否定詞、條件或例外的句子；
- 兩句看似重複但主詞、數字或結論不同的內容；
- 技術名詞重講、完整句子或敘事順序變更；
- 任何可能改變原始主張的片段。

共同規則：刪除較早的失敗嘗試，保留後面完整說法；不確定時保留；不可切斷字尾或音節。

## 6. 平台與短／中／長時長規格

括號內是建議目標秒數；區間是可接受的編輯範圍：

| 平台／畫幅 | 短 short | 中 medium | 長 long |
|---|---:|---:|---:|
| 通用直式 9:16 | 15–30 秒（30） | 45–90 秒（60） | 120–180 秒（180） |
| Instagram Reels 9:16 | 15–30 秒（30） | 45–90 秒（60） | 120–180 秒（180） |
| YouTube Shorts 9:16 | 15–30 秒（30） | 45–60 秒（60） | 90–180 秒（180） |
| TikTok 9:16 | 15–30 秒（30） | 45–90 秒（60） | 120–300 秒（180） |
| 小紅書 3:4／9:16 | 15–30 秒（30） | 45–60 秒（60） | 90–180 秒（120） |
| YouTube 橫式 16:9 | 60–180 秒（120） | 300–600 秒（480） | 600–1200 秒（900） |

這些是本 Skill 的編輯建議，不是平台上傳上限。Instagram 官方說明目前允許最長 20 分鐘 Reels，但超過 3 分鐘不會推薦給新受眾，因此本矩陣把長版發現型內容控制在 180 秒內；YouTube 官方將方形或直式、最長 3 分鐘的影片歸類為 Shorts；TikTok Studio 網頁上傳說明目前列出最長 30 分鐘，但那是上傳能力而不是最佳剪輯長度。本 Skill 因此把 TikTok 長版的首版編輯上限設為 300 秒。小紅書與 YouTube 橫式列的是編輯工作預設，不宣稱是官方技術上限。

官方依據：[Instagram Reels 長度與推薦](https://www.facebook.com/help/instagram/225190788256708)、[YouTube Shorts 最長 3 分鐘](https://support.google.com/youtube/answer/15424877?hl=en)、[TikTok Studio 上傳規格](https://support.tiktok.com/en/using-tiktok/creating-videos/creator-tools-on-tiktok?lang=nl)。平台規則會變動；若下一階段加入實際發佈，發佈前必須重新查核。

套用規則：

- 使用者指定秒數時優先，例如「75 秒」會覆寫短／中／長，但仍以語意完整為先。
- 使用者指定平台與級距時，直接採用表格對應範圍。
- 使用者要求 `auto` 時，Agent 讀完本機逐字稿後，選擇足以容納一個完整主張的最小級距；若沒有任何級距能容納完整內容，採長版並挑最強的完整連續段落。
- 使用者只說短／中／長但沒說平台時，採「通用直式」；只說平台但要求自動剪精華時，由 Agent 選級距。
- 沒有提出精華、縮短、平台或級距需求時，維持 `full` 全長清理，不擅自濃縮。
- 原片短於目標時保留實際長度，不補空白、不重複、不為湊秒數而加速或減速。
- 實際成品可以超出建議目標，但 Agent 必須回報平台、級距、目標區間與實際秒數。
- 字幕、標題與動畫不是第一階段必填輸出；使用者要求時才啟用進階流程。

## 7. 完成條件

Agent 只有在下列條件成立時才能回報完成：

- 原始影片仍存在且未被修改；
- 新 MP4 存在、大小大於零，ffprobe 能讀到有效時長與視訊串流；
- 原片有音訊時，成品也有音訊，除非使用者明示靜音；
- 所有實際刪除範圍都有可追溯的決策或使用者指示；
- `qa_video.py` 沒有回傳阻斷狀態；
- Agent 回報實際成品，而不是只回報計畫、manifest 或預覽網址。

## 8. 第一階段不做的事

- 不要求或啟動網頁操作介面；倉庫內既有頁面編輯器屬選配，不是本階段完成條件。
- 不傳送到 LINE、Email、雲端硬碟或社群平台。
- 不把影片、音訊或逐字稿上傳到臨時公開服務。
- 不自動使用雲端 TTS、聲音複製、外部 B-roll 或未授權素材。
- 不使用 CapCut，也不修改 CapCut 草稿。

## 9. 執行環境

Agent 必須能存取本機檔案系統並執行 Python、ffmpeg 與 ffprobe。完整語意剪輯另需本機 Whisper 相容轉錄引擎；缺少轉錄引擎時，Agent 應誠實回報只能做機械式停頓清理，不得假裝已完成語意精華選段。

純瀏覽器聊天介面若不能讀取本機檔案或執行命令，即使看得到 `SKILL.md`，也不能執行這個流程。

## 10. 下一階段

頁面預覽、拖拉時間軸、可視化平台／時長控制、字幕樣式、標題卡、動畫與封面列入下一階段。第一階段已支援 Agent 以自然語言或 CLI 選擇平台與時長，但不建立介面；既有進階元件不得阻擋 Agent-first 的 A-roll 輸入與 MP4 輸出。
